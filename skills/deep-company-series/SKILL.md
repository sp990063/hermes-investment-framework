# 深度公司系列:8 篇長文拆一間公司 (Hermes port)

為 $ARGUMENTS 撰寫一個 8 篇深度長文系列,發布喺公眾號 / 視頻號等公開渠道。**核心 IP 唔係「會寫」,而係「會改」— 99% 嘅財經文章喺違反本 skill 嘅事實核查標準。**

參考樣本:`reports/騰訊/《看懂騰訊》/`

---

## 一、觸發場景

用戶希望為一間公司做「教科書級別」嘅深度研究,並以**系列長文**形式公開發布。區別於一篇研報:
- 8 篇約 12 萬字,從認知重置到決策框架完整閉環
- 每篇獨立成文(適合單篇分享),但貫穿一套估值 / 管理層 / 價格判斷
- 寫俾「願意花 90 分鐘讀懂一間公司」嘅讀者,唔係寫俾券商客戶

**唔適合用本 skill 嘅場景**:單篇研報、季報點評、行業研究 — 嗰啲用 `/investment-research`、`/earnings-review`、`/industry-research`。

## 三、寫作風格規範

### 語氣

- **直接、犀利、唔講廢話** — 第一句就俾數字或反常識結論
- **價值投資框架** — 巴菲特 / 芒格 / 段永平 / 李錄視角穿插(但唔堆砌名言)
- **唔預設立場** — 先擺數據、再推邏輯、最後得結論
- **呈現正反兩面** — 每個核心判斷都附「但另一方面...」嘅反方
- **公眾號體感** — 前 18-20 字必須能獨立企住(手機預覽)

### 禁用詞

| 禁用 | 原因 | 替代 |
|---|---|---|
| 顯然 / 必然 / 一定 | 主觀絕對化 | 數據顯示 / 證據表明 |
| 我認為 / 我覺得 | 主觀腔調 | 刪除或改為「按本框架」 |
| 教科書級別 / 神來之筆 | 流量黨褒獎 | 描述具體事實 |
| 嚴重不匹配 / 嚴重低估 | 強主觀詞 | 俾具體折讓百分比 |
| 完美 / 無可挑剔 | 單邊判斷 | 加上反方觀察 |

### 標題風格

- 用**反差數字**或**反共識結論**做鈎子(「15 年 7 次挑戰全失敗」、「年薪 4292 萬佔利潤 0.0017%」)
- 副標題中性、概括內容(「— `<本質判斷>`」)
- **避免流量黨比喻**：「小巴菲特」、「中國版 X」、「YYDS」一律避開
- 用專業讀者熟悉嘅術語(「伯克希爾」而不是「巴菲特」,公司名優於人名)

## 四、嚴苛事實核查 Checklist(核心 IP)

### 寫之前就要警惕嘅「偽精確」陷阱

1. **概率加權期望值**:`30% × A + 50% × B + 20% × C = 期望 +X%` 呢種計算幾乎全係垃圾 — 概率分配係純主觀,俾讀者錯誤精確感。**只列情景 + 觸發條件 + 方向,唔算加權期望**。
2. **第三方測算 MAU / 份額**:QuestMobile / 七麥 / CBNData 等口徑差異巨大(同一時點能差 2-3 倍)。**只用最可信嘅兩個對比作 anchor,其他做定性描述**。
3. **歷史增速線性外推**:`2025 年 +33% × 5 年複合 → 2030 年 X` 係金融文盲式預測。**情景假設 + 高 / 低區間 + 唔係承諾**。
4. **未公開嘅持股比例**:字節、Halti 類未上市公司持股**從未公開披露**。**俾區間,標「不可知」**。
5. **強歸因**:競爭對手失敗 = 因為 X。多重原因都列出嚟,**本文唔做單一歸因**。

### 修訂時必跑嘅 7 項檢查

```
□ 1. 跨篇數字一致性:總市值、Non-IFRS 淨利潤、關鍵持股 % 全系列對齊
□ 2. 口徑標註:Non-IFRS / GAAP / Non-IFRS-SBC / FCF 各用邊個,全文清楚
□ 3. 重複加計掃描:已並表子公司唔喺「投資組合」裡、SOTP 唔雙算
□ 4. 橫向比較公平性:唔能「主業 PE(剔除現金 + 組合)」 vs 「對手 PE(不剔)」
□ 5. 概率加權全刪:見上一條
□ 6. 絕對化表述全弱化:grep "顯然|必然|嚴重|教科書|完美"
□ 7. 第三方數據來源標註:每條非財報數據後跟「(來源:X)」
```

### 模型偏好

寫之前**先列出已知硬錯誤風險**:
- 歷史回報倍數:必須用累計投入口徑(如 Riot 33 倍 唔係 58 倍)
- 持股比例:必須睇最新富途 / 財報口徑(如騰訊持有美團 1.5% 唔係 6.4%)
- 「派息分派」會計處理:視同處置收益按 IFRIC 17 在宣派日確認(如京東喺 2021,美團喺 2022 但金額小)
- 總股本會反彈:SBC 集中年初授予會讓股本短期上升

## 五、執行流程

### 階段 1:調研(寫 01-02 篇前完成)

1. 閱讀公司近 5 年年報、最新季報
2. 閱讀至少 3 份獨立賣方研報(搵共識 + 反共識)
3. 用 `/investment-team` 或 `/investment-research` 先生成內部研究底稿
4. 與用戶確認 8 篇嘅核心論點(避免寫完先發現方向唔啱)

### 階段 2:寫作(按 01 → 08 順序寫,唔跳)

- 每篇寫完先存 `reports/{公司名}/《看懂{公司名}》/0X-XX.md`
- 唔立即推 GitHub — 等用戶審閱
- 用戶提修訂意見後修改
- 修訂完先 git push

### 階段 3:跨篇一致性掃描(08 篇全部寫完後)

派 Explore subagent 並行掃描 8 篇做以下檢查:

> **Hermes 限制**:Batch 最多 3 個。我哋將 8 篇分成 3 個 batch,每個 batch 嘅 subagent 負責 2-3 篇嘅一致性檢查 + 一個「最後兜底」嘅跨 batch check。

```
tasks = [
  {"goal": "檢查 01-03 篇嘅一致性", "context": "...", "toolsets": ["file"]},
  {"goal": "檢查 04-06 篇嘅一致性", "context": "...", "toolsets": ["file"]},
  {"goal": "檢查 07-08 篇嘅一致性 + 跨批 summary", "context": "...", "toolsets": ["file"]}
]
```

每個 agent 檢查:
1. 同一數字(市值、淨利潤、持股比例)跨篇是否一致
2. 同一術語(FBS、SBC、Non-IFRS)首次出現是否解釋
3. 引用關係:02 篇話「詳見 06 篇」是否真嘅對應
4. 要點回顧 vs 正文是否數字一致

### 階段 4:發布前最終核查

```bash
# 推送前必須本地 grep 一次(按 ai-berkshire 隱私規則)
grep -r "<本機用戶名>\|/Users/\|<個人身份信息>" reports/ | head
```

確認無誤先 `git pull --rebase && git commit && git push`。

## 六、修訂意見處理流程

用戶俾修訂意見時,按以下順序處理:

### 1. 先核查事實(唔好直接改)

如果用戶話「X 數據唔啱」,先用 Bash / Read 搵原始數據交叉驗證:
- 睇 ai-berkshire 項目裡同公司嘅 earnings / 財報報告
- 睇富途 / 官方披露
- 俾出「用戶講嘅數據 vs 我查到嘅數據 vs 我之前用嘅數據」三方對比

### 2. 判斷修訂級別

| 級別 | 類型 | 處理 |
|---|---|---|
| 🔥 硬錯誤 | 數字錯、歸因錯、口徑錯 | 必改,唔需猶豫 |
| ⚠️ 主觀化 | 強主觀詞、絕對化、流量黨比喻 | 弱化或刪除 |
| 🔬 顆粒度 | 來源標註、口徑細化 | 優先級低,按可讀性平衡 |
| ❓ 唔可靠 | 第三方測算差異大 | **刪比改更穩**(用戶明確指示) |

### 3. 修訂後聯動檢查

修一處先諗「邊啲地方仲會引用呢個數字 / 概念」。例:
- 改咗總市值 → 全系列聯動改 PE / 主業 PE / 折讓 / FCF Yield
- 改咗持股 % → 改 TOP 10 排序 + 歷史持股表 + 減持清單
- 改咗術語口徑 → 改首次定義 + 後續引用 + 要點回顧

### 4. 推送後立即報告

```
推送成功(commit hash)。
[N] 處修訂總結 [帶表]:
- 改咗咩
- 聯動改咗咩
- 仲有咩未改

下一步等指示。
```

## 七、本 skill 唔做咩

- **唔替讀者做投資決策** — 所有篇章末尾「唔構成投資建議」
- **唔預測股價** — 只俾「情景 + 觸發條件」
- **唔算「期望年化回報」加權值** — 主觀概率分配會誤導讀者
- **唔寫「X 大佬都持有」** — 用人哋嘅持倉為自己嘅判斷背書係反價值投資嘅
- **唔強求 8 篇都寫** — 如果某篇冇足夠獨立內容(如某公司管理層唔夠特別),合併到其他篇或減篇數

## 八、合規與隱私

- 所有公開報告**只用公開信息**(財報、官方披露、券商研報、知名第三方機構)
- 唔用任何**用戶個人信息**(公司花名、內部 IM、未公開持倉信息)
- 推送前必須用 grep 掃描 本機用戶名 / `/Users/` / 真實姓名 等私隱字段
- 公開署名按用戶多層身份策略,唔混用

## 一句話總結

**寫《看懂 X 系列》嘅核心能力 ≠ 寫得好,而係改得嚴** —
89% 嘅財經長文死於偽精確數字、主觀加權期望值、絕對化表述。本 skill 嘅存在就係為咗將呢啲坑全部標記出嚟,寫之前避開,寫之後掃乾淨。
