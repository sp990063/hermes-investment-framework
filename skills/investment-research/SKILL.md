# 投資研究:巴菲特-芒格-段永平-李錄 四大師綜合分析框架 (Hermes port)

對 $ARGUMENTS 進行系統化投資研究分析。本 skill 係 **single-agent sequential reflection**(順序執行 7 個模組,每個模組用對應大師視角反思),**唔係** multi-agent 並行。

如果你需要真正嘅 4 個 background subagent 並行,使用 `investment-team` skill。

---

## 研究框架

基於巴菲特、芒格、段永平、李錄四位投資大師嘅方法論,按以下 7 個模組順序執行研究:

### 前置步驟:AI 研究偏見自覺(必須執行)

喺開始研究前,先評估該公司嘅「AI 可研究性」,識別潛在嘅數據偏見:

**信息豐富度評級**:

| 等級 | 特徵 | AI 研究陷阱 | 應對策略 |
|---|---|---|---|
| A 級(信息充裕) | 上市多年、券商覆蓋多、媒體報道密集 | 共識過強,AI 輸出趨同於市場定價,alpha 有限 | 重點做反面檢驗:聰明人點解唔買?被忽略嘅風險係咩? |
| B 級(信息適中) | 上市 1-3 年、覆蓋有限、部分數據需推算 | AI 可能用「合理推測」填補空白,睇起嚟完整實則虛假確定性 | 每個推算數據標註置信度,區分「有據推算」和「憑空填充」 |
| C 級(信息稀缺) | 剛上市 / 冷門股 / 新興市場、幾乎無覆蓋 | AI 會因資料不足而過度保守,誤判為「睇唔清 = 唔好」 | 用第一性原理提問(見下方),從有限信息中提取商業本質 |

**C 級公司嘅第一性原理研究法**:

當公開資料不足時,**唔好試圖拼湊出「睇起嚟完整」嘅報告**,而係聚焦以下底層問題:
1. 客戶係邊個?點解俾錢?有冇替代選擇?
2. 複購靠咩驅動?係習慣、鎖定、還係持續創造新價值?
3. 競爭對手拎 100 億能複製呢門生意嗎?
4. 管理層做過咩關鍵決策?呢啲決策反映咗咩判斷力同價值觀?

**偏見自查清單**(研究全程保持警惕):
- [ ] 我嘅「確定性」感受係嚟自生意本質,還係嚟自資料數量?
- [ ] 如果將呢間公司嘅資料量減少一半,我嘅結論會變嗎?
- [ ] AI 輸出嘅分析是否與市場共識高度雷同?如果係,我嘅信息優勢喺邊?
- [ ] 是否存在「公開資料很少但生意本質極好」嘅可能性被低估咗?

將信息豐富度評級結果寫入報告開頭,並喺最終結論中註明「AI 研究置信度」與「實際投資確定性」嘅區別。

### 第一步:數據收集

> **數據源規範**:參見 `~/.hermes/skills/finance/financial-data/SKILL.md`。所有財務數據必須來自兩個獨立來源,誤差 > 1% 須標記。
> - 美股:macrotrends(主)+ stockanalysis(副)
> - 港股:aastocks(主)+ macrotrends ADR(副)
> - A 股:東方財富(主)+ 巨潮資訊(副)

用 `web_search` 同 `web_extract` 收集以下數據:

1. **收入結構**:最近財年及近 4 季度分部收入、增速、毛利率
2. **財務指標**:近 5 年收入、淨利潤、毛利率、經營利潤率、自由現金流、現金儲備
3. **競爭格局**:市場份額、主要競爭對手對比
4. **商業模式與護城河**:核心競爭優勢來源
5. **技術能力**:核心技術棧、研發投入
6. **管理層**:創辦人 / CEO 履歷、持股比例、關鍵決策記錄
7. **行業前景**:TAM(總可尋址市場)、增長預測
8. **風險因素**:地緣政治、監管、供應鏈等
9. **當前估值**:市值、PE、PS、PEG、EV/Revenue
10. **多空雙方核心論點**

#### 數據交叉驗證(必須執行,使用金融嚴謹性工具)

數據收集完成後,**必須調用 `~/.hermes/scripts/financial/financial_rigor.py` 對關鍵數據進行程序化驗證**,杜絕 LLM 心算誤差。

**必須驗證嘅數據點**:
- 總股本(從交易所、Yahoo Finance、StockAnalysis 等至少 2 個源確認)
- 當前股價和市值(**手動計算 股價×總股本 並與報告市值對比,防止單位錯誤**)
- 最近財年收入和淨利潤(從公司年報+至少 1 個第三方源確認)
- 現金儲備和淨現金(現金+短期投資-總債務,注意口徑差異)
- 管理層持股比例(區分經濟權益和投票權,注意 AB 股結構)

**強制驗證步驟(使用 Bash 調用工具)**:

```bash
# Step 1 — 市值驗算(精確十進制,非浮點)
python3 ~/.hermes/scripts/financial/financial_rigor.py verify-market-cap \
  --price {股價} --shares {總股本} --reported {報告市值} --currency {幣種}

# Step 2 — 關鍵數據多源交叉驗證
python3 ~/.hermes/scripts/financial/financial_rigor.py cross-validate \
  --field {字段名} \
  --values '{"來源1": 數值, "來源2": 數值}' \
  --unit {單位}

# Step 3 — 估值指標精確驗算(PE/PB/ROE/FCF Yield 等)
python3 ~/.hermes/scripts/financial/financial_rigor.py verify-valuation \
  --price {股價} --eps {EPS} --bvps {每股淨資產} \
  --fcf-per-share {每股FCF} --dividend {每股股息}
```

對收入、淨利潤、現金儲備分別執行驗證。

**驗證規則**:
1. 每個關鍵數據點至少 2 個獨立來源
2. 發現來源間有差異時,優先採用公司年報 / 交易所數據,並註明差異原因
3. **所有涉及計算嘅數據必須通過工具驗算,禁止 LLM 心算**
4. 工具輸出結果直接嵌入報告附錄「關鍵數據交叉驗證記錄」
5. 如果工具報告 ❌ 偏差過大,必須排查原因後才能繼續分析

**常見錯誤防範**:
- 市值單位:港幣億 vs 人民幣億 vs 美元億,容易漏寫 / 多寫一個零
- FCF 口徑:不同來源對資本支出嘅定義可能不同(是否含租賃、收購等)
- 債務口徑:是否包含經營租賃負債
- 持股比例:AB 股公司嘅經濟權益 ≠ 投票權

### 第二步:生意本質分析 — 段永平「對嘅生意」

分析要點:
- 用一句話定義呢門生意嘅本質
- 收入結構拆解(圖表)
- 5 年盈利能力趨勢(圖表)
- 商業模式畫布:一次性銷售 vs 訂閱 / 複購?硬件 vs 軟件 vs 平台?
- 生態粘性 / 客戶鎖定強度
- 毛利率水平與同行對比,解釋點解高 / 低
- 經營槓桿分析
- **段永平式追問**:呢門生意好喺邊?如果只能用一句話描述,係咩?

### 第三步:護城河評估 — 巴菲特「經濟護城河」

逐一驗證五類護城河:

| 護城河類型 | 驗證方法 |
|---|---|
| 品牌 / 定價權 | 是否能在不損失銷量嘅情況下提價? |
| 轉換成本 | 客戶遷移到競品嘅成本有幾高? |
| 網絡效應 | 用戶越多產品越好嗎? |
| 規模效應 | 規模帶來嘅成本優勢有幾大? |
| 技術 / 專利壁壘 | 技術領先幾年?能否被複製? |

分析護城河趨勢:過去 5 年變寬還是變窄?未來 5 年預判。

**巴菲特式追問**:10 年後呢條護城河仲喺度嗎?咩能摧毀佢?

### 第四步:逆向思考與風險清單 — 芒格「反過嚟想」

- 列出「呢間公司可能失敗嘅所有路徑」(表格:路徑 / 概率 / 影響程度)
- 歷史類比:搵到歷史上處於相似位置嘅公司,結局如何?
- 跨學科分析:用網絡效應理論、技術採納曲線、競爭博弈等模型交叉驗證
- 偏誤自查:敘事偏差、錨定效應、倖存者偏差
- 收集空方核心論點

**芒格式追問**:我最適可能喺邊度犯錯?聰明人點解會唔買 / 做空呢間公司?

### 第五步:管理層評估 — 段永平「對嘅人」+ 巴菲特「管理層誠信」

- CEO / 創辦人關鍵決策復盤(表格:時間 / 決策 / 結果 / 評分)
- 資本配置能力:研發回報率、併購成功率、回購時機
- 股東利益一致性:管理層持股、薪酬結構、減持記錄
- 組織能力:團隊穩定性、關鍵人才風險
- 企業文化特徵

**段永平式追問**:如果 CEO 退休,呢間公司仲能保持競爭力嗎?

### 第六步:行業與文明趨勢 — 李錄「文明演進框架」

- 判斷所在行業係咪處於「文明級範式轉移」
- 歷史技術革命類比(蒸汽機 / 電力 / 互聯網 / AI)
- TAM 增長曲線與天花板分析
- 公司喺產業價值鏈中嘅位置
- 技術路線風險
- 客戶 / 供應商集中度分析

**李錄式追問**:企喺 20 年後回睇,呢間公司係「呢個時代嘅標準石油」還是「曇花一現嘅 3Com」?

### 第七步:估值與安全邊際 — 巴菲特「內在價值」+ 段永平「對嘅價格」

- 當前市場定價(關鍵估值指標表格)— **必須通過工具驗算**
- 反向 DCF:當前股價隱含咗咩增長預期?
- **三情景估值 — 必須通過工具精確計算,禁止心算**:

```bash
python3 ~/.hermes/scripts/financial/financial_rigor.py three-scenario \
  --price {股價} --eps {EPS} --shares {股本億} \
  --growth {樂觀增速} {中性增速} {悲觀增速} \
  --pe {樂觀PE} {中性PE} {悲觀PE} --years 3 --currency {幣種}
```

- 與自身歷史估值對比
- 與同行估值對比

**段永平式追問**:如果股市明天關閉 5 年,你願意以呢個價格持有嗎?

#### ⚠️ 虧損公司估值替代方案

`three-scenario` 對**虧損或 zero-EPS 公司無用**(future_eps × exit_pe → 0)。常見於:
- 大模型 / AI 公司(MiniMax, 智譜 GLM, OpenAI pre-profit)
- Biotech(pre-revenue)
- 早期 SaaS(burn phase)

**改用 P/ARR 倍數法**:

```
2026E ARR × 退出倍數 = 隱含市值
```

**退出倍數對標**:
| 公司類型 | 退出倍數 |
|---|---|
| OpenAI 級別(全棧 + 護城河深) | 25-40x ARR |
| 開源領導者(Meta Llama, GLM 角色) | 20-25x ARR |
| 中間層 specialist | 12-20x ARR |
| 高度投機 / 早期 | < 15x ARR |

範例(MiniMax 2026-07 估值):
- 樂觀: ARR US$600M × 30x = US$18,000M(+205% vs IPO US$5.9B)
- 中性: ARR US$300M × 20x = US$6,000M(+1.6%)
- 悲觀: ARR US$150M × 12x = US$1,800M(-69.5%)

**檢查項**:估算 2026E ARR 時,要引用招股書最新披露嘅 ARR 或公司年報「annualized revenue」,**唔好用認列營收做 ARR**(尤其大模型公司認列 vs 訂閱有時間差)。

#### Runway 計算

對**燒錢 phase 公司**(典型 startup / pre-profit),必須額外計算:

```
runway = 賬上現金 / 經調整年淨虧損
```

| Runway | 評估 |
|---|---|
| > 5 年 | ✅ 健康 |
| 3-5 年 | ⚠️ 注意,需要 ARR 持續爆發 |
| 1.5-3 年 | ❌ 緊,極可能要再融資(攤薄 20-30%) |
| < 1.5 年 | 🚨 危險,接近死亡之谷 |

## 輸出要求

1. 所有分析必須有數據支撐,附數據來源
2. 使用 Markdown 表格呈現關鍵數據
3. 每個模組末尾必須有對應大師嘅「追問」
4. 最終將完整報告寫入 `~/[公司名]投資研究報告.md`
5. 結論要明確,不迴避給出買入 / 觀望 / 迴避嘅建議
6. 估值部分必須給出具體嘅價格區間
7. **報告開頭**必須包含「信息豐富度評級」(A/B/C)和「AI 研究局限性聲明」
8. **報告結尾**必須區分「AI 分析置信度」與「投資確定性」— 前者取決於資料量,後者取決於生意本質。明確告知讀者:本報告嘅邊啲結論基於充分數據,邊啲基於有限信息嘅推理
9. 如果公司屬於 C 級(信息稀缺),報告末尾必須列出「需要一手驗證嘅問題清單」— 建議讀者通過田野調查、產品體驗、供應鏈訪談等方式補充 AI 嘅盲區

## 數據抽檢(準出流程)

報告寫入文件後,**必須**執行數據抽檢,通過後方可發布:

**Step 1 — 提取抽檢清單(15% 隨機抽樣)**:

```bash
python3 ~/.hermes/scripts/financial/report_audit.py extract \
  --report <報告文件路徑>
```

輸出 JSON 模板,每項含 `fetched_value`(待填)。

**Step 2 — 取數核驗**:

對清單中每個數據點,按 `financial-data` 規範從可靠信源取數,填入 `fetched_value` / `fetched_source` / `fetched_value2` / `fetched_source2`。

**Step 3 — 輸出判決**:

```bash
python3 ~/.hermes/scripts/financial/report_audit.py verdict \
  --results '<填好嘅 JSON>' \
  --report <報告文件名>
```

- **【準出】**:所有抽檢點偏差 ≤ 1% → 報告可發布
- **【打回】**:任意點偏差 > 1% → 修正對應數據後重新抽檢,直到準出
