# 未上市公司研究:多 Agent 並行深度研究框架 (Hermes port)

對 $ARGUMENTS 進行團隊化深度研究分析。專為螞蟻集團、小紅書、SpaceX、Stripe 等未上市公司設計。

**最終目標**:喺信息天然稀缺嘅條件下,盡可能還原呢間公司嘅**真實價值** — 唔係市場俾嘅估值,而係生意本身值幾錢。

---

## 框架特點

未上市公司 vs 上市公司研究嘅核心差異:
- **無標準化財報**:需多源拼湊、交叉驗證
- **估值錨定少**:依賴融資輪次、可比公司法、情景推演
- **信息不對稱大**:需要更多「拼圖式」研究方法
- **退出路徑不確定**:IPO / 併購 / 二級轉讓均有可能

## AI 研究偏見自覺(本框架嘅核心前提)

未上市公司係 AI 研究偏見最嚴重嘅領域。必須時刻警惕以下陷阱:

**核心矛盾**:AI 擅長結構化已有信息,但未上市公司嘅信息天然稀缺。呢個會導致:
1. **虛假保守**:因為資料少,AI 傾向俾出保守 / 模糊嘅結論,但資料少 ≠ 公司唔好
2. **虛假精確**:為咗填滿報告模板,AI 可能用「合理推測」偽裝成「有據分析」
3. **對標陷阱**:強行與上市公司對標時,會繼承上市公司嘅估值邏輯,忽略未上市公司嘅獨特價值
4. **倖存者偏差**:網上能搜到嘅公司信息往往有正面偏向(公司主動傳播嘅多係好消息)

**應對原則**:
- 寧可留白講「唔知道」,亦唔好用推測填滿表格偽裝確定性
- 每個數據點必須標註置信度(🟢高 / 🟡中 / 🔴低),讓讀者自己判斷
- 區分「可驗證嘅事實」與「AI 嘅推理」,用唔同格式標註
- 對於信息極度稀缺嘅公司,切換為「第一性原理模式」 — 唔追求報告完整,只回答幾個核心問題:
  1. 呢門生意解決咩真實問題?需求係真需求還是偽需求?
  2. 點解係呢個團隊?佢哋有咩獨特優勢?
  3. 如果成功咗,天花板有幾高?如果失敗咗,最適可能死喺邊?
  4. 當前階段嘅關鍵驗證節點係咩?

**反向利用信息不對稱**:市場對未上市公司信息少 → 定價效率低 → 恰恰可能係超額收益嘅來源。AI 研究嘅目標唔係消除信息不對稱(做唔到),而係喺有限信息中提取最關鍵嘅判斷依據。

## 執行流程

### 第一步:展示團隊框架

向用戶展示以下團隊結構,確認後啟動:

| 角色 | 職責 | 核心視角 |
|---|---|---|
| **team-lead**(你自己) | 統籌協調、信息拼圖、交叉驗證、輸出最終報告 | 投資決策整合 |
| **business-decoder** | 商業模式拆解 & 產品用戶分析 | 「呢門生意嘅本質係咩」 |
| **financial-detective** | 財務數據拼湊 & 估值推演 | 「喺信息缺失下盡可能還原真實財務面貌」 |
| **competitive-mapper** | 行業格局 & 競爭態勢 & 替代威脅 | 「邊個喺同佢競爭,邊個可能顛覆佢」 |
| **risk-governance-analyst** | 風險全景 & 管理層 / 治理 / 投資人評估 | 「咩可能出錯,邊個喺掌舵」 |
| **tech-ip-analyst** | 技術棧 / 專利 / 研發能力 / 技術護城河 | 「技術壁壘係真係假,能撐幾耐」 |
| **signal-miner** | 替代數據挖掘:招聘 / 專利 / 訴訟 / App 數據 / 供應鏈 | 「常規信息之外,仲有咩蛛絲馬跡」 |

### 第二步:啟動 3 個並行 subagent(Hermes batch 限制)

> **Hermes 限制**:Batch mode 最多 3 個 task。本 skill 將 6 個任務合併為 3 個 batch。

| Subagent | 合併任務 |
|---|---|
| **agent-1** | business-decoder + tech-ip-analyst(合併商業 + 技術) |
| **agent-2** | financial-detective + signal-miner(合併財務 + 替代數據) |
| **agent-3** | competitive-mapper + risk-governance-analyst(合併競爭 + 風險) |

每個 agent 收到自己嘅 goal + context,獨立研究 + 交叉驗證,獨立寫一份 markdown report,返回 summary。

完成後可選擇性 spawn 第 4 / 5 / 6 個 sequential agent 做深度補充,但通常 3 份足以 cover framework。

### 第三步:Agent 詳細 prompt(供 team-lead 參考)

#### Agent 1 — 商業 + 技術(business-decoder + tech-ip-analyst)

**業務部分必須涵蓋**:
1. **核心生意定義**:用一句話定義呢門生意嘅本質(段永平式定義:用最樸素嘅語言,將呢門生意講俾一個聰明但唔識行嘅人聽);公司解決咩問題?為誰創造價值?價值主張同同類產品嘅差異化;呢個問題如果公司唔存在,用戶會點解決?替代方案嘅代價有幾高?需求嘅「剛性」判斷:經濟下行時用戶會砍掉呢個支出嗎?
2. **收入模式拆解**:收入構成(廣告 / 佣金 / 訂閱 / 交易抽成 / 金融服務 / SaaS / 硬件 / 授權費等);各收入線佔比(如有數據)及增長趨勢;變現效率指標推算:ARPU、Take Rate、廣告加載率、轉化率等;收入質量評估:經常性收入 vs 一次性收入嘅佔比;收入集中度:前 5 大客戶 / 渠道佔比;收入嘅可預測性(合同型 / 訂閱型 vs 交易型);收入確認方式是否合理(有無提前確認收入嘅跡象);與同業上市公司變現效率對標
3. **單位經濟模型(UE)推算**:CAC(獲客成本)推算;LTV(生命週期價值)推算;LTV/CAC 比值;Payback period
4. **產品矩陣與飛輪效應**
5. **商業模式畫布(BMC)**
6. **用戶深度分析**
7. **定價權評估**
8. **護城河評估**
9. **國際化分析**(如適用)

**技術部分必須涵蓋**:
1. **技術棧分析**:使用咩語言 / 框架 / 雲服務商?有冇技術債務?
2. **專利布局分析**:核心專利數量、地理覆蓋、被引用次數、剩餘有效期
3. **研發能力評估**:研發人員比例、頂級人才密度、學術發表、行業影響力
4. **技術護城河真實性**:係咪真嘅難以複製,還是表面嘅 barrier?

#### Agent 2 — 財務 + 替代數據(financial-detective + signal-miner)

**財務部分必須涵蓋**:
1. **數據來源矩陣**:招股書(如有)、母公司財報、新聞報導、行業協會數據、招聘信息(可推算成本)、監管文件、專利數據、行業報告、融資估值歷史
2. **關鍵財務指標推算**:收入規模、毛利率、用戶數、ARPU、付費轉化率(每個指標標 🟢🟡🔴)
3. **財務數據交叉驗證**:多源拼湊,差異 > 1% 須標註
4. **融資歷史與估值演變**:每輪估值、稀釋比例、投資人陣容、Pari passu 條款
5. **估值分析(多方法交叉)**:
   - 融資估值法(考慮流動性折讓、二級市場溢價)
   - 可比公司法(類似上市公司 EV/Revenue 倍數)
   - DCF(高敏感度,多情景)
   - 終局倒推法(假設成功,合理市值)
6. **估值綜合判斷**

**替代數據部分必須涵蓋**:
- 招聘信息(招聘網站 / LinkedIn / 公司官網):職位數量、關鍵崗位、技術棧暗示嘅戰略方向
- 專利申請趨勢:頻率、技術方向、地理分布
- 訴訟記錄:原告被告、頻率、結果
- App 數據:下載量趨勢、評分變化、活躍用戶
- 供應鏈信號:招標記錄、合作公告

#### Agent 3 — 競爭 + 風險(comitive-mapper + risk-governance-analyst)

**競爭部分必須涵蓋**:
1. **行業定位與市場規模**:TAM / SAM / SOM,增速,滲透率
2. **產業鏈全景地圖**:上中下游、價值分配
3. **波特五力分析(量化打分)**:現有競爭對手、新進入者威脅、替代品、買方議價能力、供應商議價能力
4. **競爭格局深度掃描**:CR3、CR5、HHI 指數
5. **競爭對手深度對比**
6. **競爭動態與趨勢**:未來 3-5 年競爭格局演變
7. **競爭情景推演**:護城河被打破嘅可能性、收購整合趨勢
8. **全球對標分析**

**風險部分必須涵蓋**:
1. **創辦人 / CEO 深度評估**:能力圈、誠信、過往成功 / 失敗記錄
2. **核心團隊評估**:聯合創辦人、CTO、關鍵高管嘅背景同穩定性
3. **股權結構與治理**:普通股 / 優先股、VIE、雙重股權、董事席位
4. **投資人陣容深度分析**:領投方、跟投方、戰略投資者嘅價值(信號 vs 純錢)
5. **全維度風險清單**:市場、技術、政策、競爭、財務、人員、合規
6. **退出路徑分析**:IPO(時間表 / 概率)、併購(潛在買家)、二級轉讓(流動性)
7. **最壞情景分析(芒格式逆向思考)**

### 第四步:數據交叉驗證

每個 agent 嘅數據點必須:
- 標註置信度 🟢(≥2 個獨立來源吻合)/ 🟡(單一來源 + 推理)/ 🔴(僅推測)
- 列出所有來源 URL
- 多源差異 > 1% 須明確標註同說明可能原因

### 第五步:綜合最終報告

```
一、公司速覽(一句話定義 + 🟢🟡🔴 速覽)
二、商業模式深度拆解(Agent 1 整合)
   - 核心生意 + 收入模式 + UE 模型 + 護城河
三、技術與知識產權(Agent 1)
四、財務拼湊與估值(Agent 2)
   - 數據來源矩陣
   - 推算財務指標
   - 4 種估值方法交叉
   - 合理估值區間(低 / 中 / 高)
五、競爭格局(Agent 3)
   - 行業定位 + 波特五力 + 對標分析
六、風險與治理(Agent 3)
   - 創辦人 + 股權 + 退出路徑
七、替代數據洞察(Agent 2)
八、AI 研究的局限(置信度聲明)
九、最終估值判斷與投資建議
```

### 第六步:保存報告

寫入 `reports/{公司名}-private-{YYYYMMDD}.md`。

## 工具整合

用 `~/.hermes/scripts/financial/financial_rigor.py` 做估值驗算:

```bash
# 推算嘅市值驗算
python3 ~/.hermes/scripts/financial/financial_rigor.py verify-market-cap \
  --price {推算每股} --shares {推算股本} --reported {融資估值} --currency USD

# 多源估值交叉
python3 ~/.hermes/scripts/financial/financial_rigor.py cross-validate \
  --field "company_valuation" \
  --values '{"forge_market": 350000000000, "media_estimate": 320000000000}' \
  --unit USD
```

## 重要注意事項

1. **🟢🟡🔴 置信度標註係核心**:唔好為咗睇起嚟專業而隱藏不確定性
2. **C 級信息嘅 first-principles mode**:資料極度稀缺時,**唔好強行填滿模板**,只回答 4 個核心問題
3. **退出路徑分析係必須嘅**:未上市公司嘅投資價值取決於流動性
4. **流動性折讓**:二級市場估值通常比一級市場低 20-40%(對沖基金視乎鎖定期)
5. **創辦人股權稀釋追蹤**:每輪融資嘅稀釋比例必須清楚標註
6. **對標上市公司嘅侷限**:未上市公司嘅獨特價值(如戰略牌照、特殊資產)無法用上市公司邏輯捕捉

## Token 控制

本 skill 涉及 6 個獨立維度嘅研究 + 估值,token 消耗高。建議:
- 真正嘅 high-conviction 決策先用本 skill
- 對一般未上市公司,先用 `quality-screen` skill 篩過
- 投資 thesis 確認值得先深入,先運行本 skill
