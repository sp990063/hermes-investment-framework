# 財報精讀:一手資料深度解讀 (Hermes port)

對 $ARGUMENTS 進行財報精讀分析。

**支持輸入格式**:`公司名 季度`,例如:`騰訊 2025Q4`、`PDD 2025年報`、`美團 最新`(默認讀取最近一期)

> 「我從唔睇賣方研報,只讀原始財報。」 — 李錄
>
> 「我每日讀 500 頁。知識就係咁累積嘅,像複利一樣。」 — 巴菲特

---

## 設計理念

大多數 AI 投研工具依賴二手信息(新聞、研報摘要、數據網站)。但巴菲特和李錄嘅核心能力係**讀一手資料** — 年報、季報、電話會紀要。

二手信息嘅問題:
- 被篩選過 — 分析師選擇性呈現對其觀點有利嘅數據
- 有時滯 — 等人哋消化完,alpha 已經冇咗
- 缺乏語境 — 「收入增長 15%」脫離咗管理層對增長質量嘅討論

本 skill 直接解讀一手資料,關注巴菲特和李錄真正會睇嘅內容。

## 執行流程

### 前置步驟:資料可得性評級

| 等級 | 特徵 | 影響 |
|---|---|---|
| **A 級** | 獲取到完整原文(10-K / 年報 / 電話會紀要) | 正常執行全部步驟 |
| **B 級** | 僅獲取到部分原文或第三方匯總 | 標註「非原始來源」,降低附注分析權重 |
| **C 級** | 僅有新聞報道和數據網站摘要 | 聚焦核心財務數據變化,跳過附注挖掘,標註「一手資料不足」 |

### 第一步:獲取一手資料

> **Hermes adaptation**:用 `delegate_task` 啟動 3 個 batch subagent 並行獲取材料(batch 限制下合併「電話會紀要」+「股東信」為一個 task)。

| Subagent | 任務 |
|---|---|
| **agent-1** | 財報原文 PDF / HTML(從公司 IR、SEC EDGAR、港交所披露易、巨潮資訊網) |
| **agent-2** | 業績電話會紀要 / 錄音 + 管理層致股東信 |
| **agent-3** | 投資者日 / 分析師日材料(如有近期) |

如果無法獲取完整原文,按 `~/.hermes/skills/finance/financial-data/SKILL.md` 規範使用標準數據源拼湊(美股:macrotrends + stockanalysis;港股:aastocks + macrotrends;A 股:東方財富 + 巨潮資訊),但必須標註「非原始財報,來自第三方匯總」,且關鍵數據兩源誤差 > 1% 須標記。

### 第二步:核心財務數據提取與驗證

#### 2.1 收入與利潤表

| 指標 | 本期 | 上期 | YoY 變化 | 管理層指引 | 是否達標 |
|---|---|---|---|---|---|

必須覆蓋:
- 總收入及分業務 / 分地區收入拆解
- 毛利潤、毛利率變化
- 經營利潤、經營利潤率變化(區分 GAAP 和 Non-GAAP)
- 淨利潤(注意非經常性損益嘅影響)
- EPS(基本 vs 稀釋)

**必須驗算**:用 `~/.hermes/scripts/financial/financial_rigor.py verify-market-cap` + `verify-valuation` 做市值、PE / PB / FCF yield 嘅精確驗算。

#### 2.2 現金流量表(巴菲特最看重)

| 指標 | 本期 | 上期 | 變化 | 關注點 |
|---|---|---|---|---|
| 經營活動現金流 | | | | |
| 資本開支 | | | | |
| **自由現金流** | | | | FCF margin 變化 |
| 投資活動現金流 | | | | |
| 融資活動現金流 | | | | |

**巴菲特標準**:FCF 持續增長 + 投資性 CapEx 佔收入比穩定 = 高質量盈利。

#### 2.3 資產負債表

| 指標 | 本期 | 上期 | 變化 |
|---|---|---|---|
| 現金及等價物 | | | |
| 短期投資 | | | |
| **淨現金** | | | |
| 應收賬款 | | | |
| 存貨 | | | |
| 商譽 / 無形資產 | | | |
| 總資產 | | | |
| 總負債 | | | |
| 股東權益 | | | |

**重要**:
- 區分**經濟商譽**(品牌、護城河)vs **會計商譽**(併購溢價)
- 應收賬款 / 收入比 > 20% 警示

#### 2.4 關鍵指標交叉驗證

```bash
python3 ~/.hermes/scripts/financial/financial_rigor.py verify-valuation \
  --price {股價} --eps {EPS} --bvps {每股淨資產} \
  --fcf-per-share {每股FCF} --dividend {每股股息}

python3 ~/.hermes/scripts/financial/financial_rigor.py cross-validate \
  --field "Q4_revenue" \
  --values '{"source_A": 1670000000000, "source_B": 1675000000000}' \
  --unit HKD
```

### 第三步:管理層討論(MD&A)深度解讀

> 「睇管理層點樣寫,比睇數據更重要」 — 巴菲特

**關注點**:

#### 3.1 對增長嘅定性描述
- 管理層點樣描述呢季表現?用咩形容詞?(「strong」 / 「solid」 / 「challenging」 / 「headwinds」)
- 邊啲業務被強調?邊啲被輕描淡寫?
- 用字嘅微妙變化(對比上一份報告)

#### 3.2 對未來嘅指引
- 管理層有無給具體指引?邊啲指標?
- 指引嘅信心程度(具體數字 vs 含糊辭令)
- 「We expect...」 / 「We anticipate...」 / 「We hope...」(越後越弱)

#### 3.3 風險因素嘅增刪
- 對比上一份報告,風險章節有冇新加入嘅風險?
- 有冇刪走舊風險?(可能意味住問題已解決 / 或者刻意淡化)

#### 3.4 非常規交易
- 有無 SBC(股票薪酬)大幅變化?
- 有無重大商譽減值?
- 有無一次性損益?佔比幾多?

### 第四步:電話會重點

用 `web_search` + `web_extract` 搵電話會 transcript / 重點摘要。關注:

#### 4.1 預期管理
- CEO / CFO 有無主動調整市場預期?(比分析師預期低 / 高)

#### 4.2 分析師追問
- 邊啲問題被輕鬆答到?邊啲問題有迴避跡象?
- 有無「我們喺呢方面唔方便分享」?

#### 4.3 具體數字 vs 模糊回應
- 邊啲問題俾到具體數字?邊啲得「我們會持續關注」等模糊回應?

### 第五步:附注挖掘(進階)

> 「睇附注嘅人 100 個入面得 1 個」 — 巴菲特

關注:
1. **收入確認政策** — 邊啲收入有提前確認跡象?
2. **客戶集中度** — 前 5 大客戶佔比(如有披露)
3. **關聯交易** — 與母公司 / 大股東嘅交易
4. **訴訟撥備** — 有無新嘅重大訴訟撥備?
5. **會計政策變更** — 有無 switch 過會計準則?為咩?
6. **後續事件** — 報告日後嘅重大事件

### 第六步:同業對標

將本期數字對比**至少 3 個同業**:
| 指標 | 本期公司 | 同業 A | 同業 B | 同業 C |
|---|---|---|---|---|

唔同公司用唔同會計準則,比較時必須**標註口徑差異**。

### 第七步:輸出財報精讀報告

#### 報告結構

```
一、資料來源說明(A/B/C 級評級)
二、核心財務數據速覽(表格)
   - 收入 / 毛利率 / 經營利潤率 / 淨利潤 / FCF
三、現金流質量分析
   - FCF margin + 對比歷史 + 同業
四、管理層討論解讀
   - 增長描述 + 未來指引 + 風險變化
五、電話會關鍵訊號
   - 預期管理 + 追問迴避 + 模糊回應
六、附注挖掘發現
   - 收入確認 / 客戶集中 / 關聯交易 / 訴訟
七、同業對標
八、財務數據交叉驗證結果
   - 用 financial_rigor 工具驗證
九、結論:呢份財報講咗咩故事?
   - 一句話總結
   - 投資論點嘅支持 / 反對
```

### 第八步:保存報告

寫入 `reports/{公司名}-earnings-{YYYYQ_N}.md`,例如 `reports/騰訊-earnings-2025Q4.md`。

## 工具整合

所有計算用 `~/.hermes/scripts/financial/financial_rigor.py` 程式化驗算,**禁止 LLM 心算**。

## 關鍵原則

- **讀一手資料**,唔信二手轉述
- **睇管理層點寫**比睇數據更重要
- **現金流先於利潤** — 巴菲特
- **附注挖掘** — 100 個入面得 1 個,但往往係最有價值嗰個
- **跨期 + 跨公司對標** — 孤立地睇一份財報冇意義

## Token 控制

一份完整財報精讀需要多輪 web_search / web_extract + 大量 markdown 寫作,token 消耗中至高。建議:
- 對**重要持倉**嘅季報 / 年報先用本 skill
- 一般追蹤用 `/news-pulse`(快速歸因)
- 嚴重關注嘅可配合 `/management-deep-dive` 一起用
