# 微信公眾號文章:作者-編輯-讀者三 Agent 協作 (Hermes port)

對 $ARGUMENTS 進行深度研究,產出一篇可直接發布嘅微信公眾號文章。三個 Agent 各司其職:作者寫深度初稿,編輯精修結構同表達,讀者從目標受眾視角審讀。

**支持輸入格式**:主題描述,例如:`大模型 OPD 技術解讀`、`Qwen3 技術報告解讀`、`點解巴菲特唔買科技股`

---

## 設計理念

一篇好嘅公眾號文章需要同時滿足三個維度:
1. **深度** — 對得起花時間讀完嘅人(作者負責)
2. **可讀性** — 結構清晰、節奏好、唔勸退(編輯負責)
3. **真係睇得明** — 目標讀者唔會喺中途放棄(讀者負責)

單人寫作容易「自嗨」 — 寫嘅人覺得清楚,讀嘅人睇唔明。三 Agent 協作嘅本質係**強制引入外部視角**。

---

## 階段一:研究與素材收集

### 第一步:明確文章定位

開始寫作之前,先確認以下信息(如用戶未指定則主動詢問):

| 維度 | 需要確認 | 默認值 |
|---|---|---|
| **目標讀者** | 技術背景程度 | 有啲技術背景但非該領域專家 |
| **文章深度** | 科普 / 中深度 / 硬核 | 中深度(有公式但要解釋清楚) |
| **文章長度** | 字數範圍 | 3,000-4,000 字 |
| **是否需要下載原始論文 / 資料** | 需要 PDF / 配圖 | 是 |
| **寫作風格** | 正式 / 對話式 / 犀利 | 對話式(像寫俾聰明嘅朋友) |

### 第二步:深度研究

> **Hermes adaptation**:用 `delegate_task` 啟動 batch subagent 並行研究。

| Subagent | 任務 |
|---|---|
| **agent-research** | 核心內容研究(論文解讀 / 技術 / 商業) |
| **agent-context** | 行業背景 + 應用 + 對比研究 |

#### Agent research 範圍

- 如果係論文解讀:下載論文 PDF、提取核心貢獻、關鍵圖表、實驗結果
- 如果係技術主題:搜尋最新進展、關鍵論文、技術細節
- 如果係商業 / 投資主題:搜尋最新數據、行業報告、競爭格局

#### Agent context 範圍

- 該技術 / 主題嘅行業落地情況
- 邊啲公司喺用?效果如何?
- 最新嘅發展趨勢同里程碑事件
- 同類方法 / 產品嘅對比、歷史發展脈絡、未來演進方向

### 第三步:整理素材框架

兩個 agent 完成後,整理出:

1. **核心論點**(一句話概括文章要傳達嘅核心信息)
2. **關鍵數據**(3-5 個最有衝擊力嘅數據點)
3. **配圖清單**(需要邊啲圖,來源係咩)
4. **文章大綱**(6-8 個章節嘅標題和核心內容)

## 階段二:作者 Agent 寫初稿

### 作者 Agent prompt 模板

**角色**:你係資深財經 / 科技作者,為目標讀者寫一篇深度文章。

**輸入**:階段一嘅素材框架。

**輸出**:3,000-4,000 字嘅 markdown 初稿。

### 目標讀者

有啲技術背景但非該領域專家。讀者願意花 15-20 分鐘讀一篇深度文章,但唔願意被 jargon 勸退。

### 寫作風格要求

- **對話式**(像寫俾聰明嘅朋友)
- **直接、犀利、唔講廢話** — 第一句就俾數字或反常識結論
- **唔預設立場** — 先擺數據、再推邏輯、最後得結論
- **呈現正反兩面** — 每個核心判斷都附「但另一方面...」嘅反方

### 核心內容

每篇文章要包含:
- **3-5 個關鍵數據**(有具體數字 + 出處)
- **1 個核心論點**(清晰可記住)
- **2-3 個反方觀點**(誠實承認唔確定)
- **1 段個人觀察**(唔係引用,係作者自身觀點)

### 文章結構要求

```
標題(反共識結論做鈎子)
副標題(<本質判斷>)

## 開頭(200-300 字)
- 前 18-20 字必須能獨立企住(手機預覽)
- 點出核心矛盾或反直覺結論

## 主體(6-8 個小節,每節 300-500 字)
- 每節有 sub-header
- 善用表格、列表、引用塊
- 配圖 2-4 張(由配圖清單提供)

## 結尾(200-300 字)
- 重申核心論點
- 邊啲情況下論點會錯?
- 「本文不構成投資建議」(如係投資主題)
```

### 配圖要求

- 每 1,000 字至少 1 張配圖
- 圖片來源必須標註
- 圖表優先(原創更好)
- 避免 stock photo(generic 圖)

### 公式要求

- 必要嘅公式可以用 LaTeX,但必須跟隨文字解釋
- 避免純公式牆(讀者會跳走)

## 階段三:編輯 Agent(sequential spawn)

**角色**:資深編輯,負責精修結構同表達。

**輸入**:作者 Agent 嘅初稿。

**任務**:
1. **結構檢查**:邏輯是否清晰?章節順序合理?
2. **節奏檢查**:邊度太長需要刪減?邊度太短需要擴充?
3. **冗餘檢查**:有冇重複嘅論點?
4. **語言檢查**:絕對化用詞(「顯然 / 必然 / 一定」)、流量黨比喻
5. **段落標題**:吸引人 + 準確反映內容?
6. **開場 200 字**:能否喺手機預覽入面 stand alone?

**輸出**:編輯過嘅版本,附修改建議清單。

---

## 階段四:讀者評審 Agent(sequential spawn)

**角色**:扮目標讀者,通讀全文。

**輸入**:編輯過嘅版本。

**任務**:
1. **可讀性**:邊度睇唔明?(技術術語 / 邏輯跳躍)
2. **節奏**:邊度悶?(可以刪走嘅段落)
3. **深度**:邊度少咗?(應該深入但無深入嘅部分)
4. **記憶點**:讀完最記得嘅 3 件事係咩?
5. **整體評分**(1-10):值唔值得讀?

**輸出**:讀者反饋 + 評分。

---

## 階段五:Team Lead 定稿

整合編輯反饋 + 讀者評審 → 最終版本。

**檢查清單**:
- [ ] 核心論點清晰可記
- [ ] 3-5 個關鍵數據都有來源
- [ ] 反方觀點有誠實呈現
- [ ] 開頭 200 字能 stand alone
- [ ] 配圖 2-4 張有來源標註
- [ ] 「本文不構成投資建議」(如係投資主題)
- [ ] 字數 3,000-4,000 字

---

## 階段六:保存 + 發布

寫入 `reports/{主題}-wechat-{YYYYMMDD}.md`。

**發布前最終檢查**:

```bash
# 推送前必須本地 grep 一次(按 ai-berkshire 隱私規則)
grep -r "<本機用戶名>\|/Users/\|<個人身份信息>" reports/ | head
```

確認無誤先 `git pull --rebase && git commit && git push`。

---

## 三 Agent 協作嘅關鍵

> **唔好因為時間壓力跳過任何一個階段**。每個 agent 嘅價值:
> - **作者**:冇人寫就冇內容
> - **編輯**:作者容易「自嗨」,需要結構化
> - **讀者**:編輯可能 over-polish,需要外部視角

跳過任何一個 = 質量下降明顯。

---

## Token 控制

`/wechat-article` 涉及 3 個 agent(2 個 research + 1 個 author)+ 1 個 editor + 1 個 reader,**5 個 LLM call 嘅 token 量**。

建議:
- 真係要發布嘅文章先用本 skill
- 草稿 / 內部討論用普通寫作
- 嚴肅認真嘅長文投資本 skill
